# sms.ir

قرارداد وب‌سرویس sms.ir و نحوهٔ استفادهٔ CRM از آن. این متن بازنویسی خود ماست، نه کپی مستندات پنل.
کلاینت در `shared/sms.ts` است و پکیج `smsir-js` یا `sms-typescript` نصب نیست. مخزن رسمی پکیج‌ها `github.com/IPeCompany` است؛ همان درخواست‌ها را می‌زنند و اعتبارسنجی اضافه ندارند.

## احراز هویت

هر درخواست هدر `x-api-key` دارد. کلید فقط در env با نام `SMS_API_KEY` است و در دیتابیس یا JSON ذخیره نمی‌شود.
`Accept` برابر `application/json` است. زمان‌ها Unix و UTC هستند.

پاسخ همیشه این شکل است:

```json
{ "status": 1, "message": "موفق", "data": {} }
```

HTTP 200 کافی نیست. `status` داخل JSON باید `1` باشد. `20` یعنی محدودیت تعداد درخواست پنل.

| HTTP | معنی |
|---|---|
| 200 | درخواست به سرویس رسیده |
| 400 | خطای منطقی |
| 401 | کلید نامعتبر |
| 429 | تعداد درخواست بیش از حد |
| 500 | خطای سمت سرویس |

## دو راه ارسال

### Verify

`POST https://api.sms.ir/v1/send/verify`

برای قالب تأییدشده: کد ورود، اطلاع‌رسانی، وضعیت سفارش. با خط خدماتی می‌رود و مسدودسازی پیامک تبلیغاتی را رد می‌کند. شمارهٔ خط در این درخواست نیست.

```json
{
  "mobile": "09120000000",
  "templateId": 123456,
  "parameters": [{ "name": "CODE", "value": "12345" }]
}
```

`name` همان نام داخل قالب است، بدون `#` دو طرف. اگر قالب `#CODE#` دارد، نام پارامتر `CODE` است. هر `value` حداکثر ۲۵ کاراکتر است. پاسخ `data.messageId` و `data.cost` است.

لینک کامل ثبت‌نام در یک پارامتر جا نمی‌شود. دامنه و مسیر باید متن ثابت قالب باشند و فقط کد کوتاه، مثلاً ۱۲ کاراکتر، پارامتر باشد.

### Bulk

`POST https://api.sms.ir/v1/send/bulk`

متن آزاد. حداکثر ۱۰۰ شماره در هر درخواست.

```json
{
  "lineNumber": 30000000000000,
  "messageText": "متن",
  "mobiles": ["09120000000"]
}
```

`sendDateTime` اختیاری و Unix UTC است. اگر خالی باشد ارسال همان لحظه است. پاسخ `packId`، `messageIds` و `cost` است.
این مسیر خط می‌خواهد. اگر خط خدماتی نباشد، گیرندهٔ لیست سیاه تبلیغاتی پیام را نمی‌گیرد.

شمارهٔ خط در CRM فقط از `resolveSenderLine()` می‌آید: خط شعبه، بعد `app_settings['sms.config'].lineNumber`، و فقط اگر آن خالی بود `SMS_SENDER_LINE`.

## قالب

| کار | درخواست |
|---|---|
| فهرست | `GET /v1/templates?pageNumber=1&pageSize=100` |
| یکی | `GET /v1/templates/{id}` |
| ساخت | `POST /v1/templates` |
| ویرایش | `PUT /v1/templates/{id}` |
| حذف | `DELETE /v1/templates/{id}` |

`id` برگشتی همان `templateId` ارسال Verify است. متن باید حداقل یک `#PARAMETER#` داشته باشد. پارامترها از خود متن استخراج می‌شوند. عنوان حداکثر ۳۲ کاراکتر و نام پارامتر حداکثر ۴۰ کاراکتر است.

وضعیت بررسی:

| status | معنی |
|---|---|
| 1 | در حال بررسی. هنوز قابل ارسال نیست و قابل ویرایش هم نیست |
| 2 | تأیید شده. تنها وضعیت قابل استفاده در Verify |
| 3 | رد شده. دلیل در `rejectionReason` |

نوع قالب: `1` کد یکبارمصرف، `2` اطلاع‌رسانی، `3` وضعیت سفارش، `100` سایر. بعضی پلن‌ها فقط قالبِ تشخیص‌داده‌شده به‌عنوان OTP را اجازه می‌دهند.

همگام‌سازی CRM یک‌طرفه است: قالب‌های پنل را می‌خواند و در `sms_templates` ذخیره می‌کند. `enabled` را عوض نمی‌کند و قالب پنل را نمی‌سازد یا ویرایش نمی‌کند.

## گزارش و حساب

- `GET /v1/send/{messageId}` وضعیت یک پیام
- `GET /v1/send/live` و `GET /v1/send/archive` ارسال‌های روز و آرشیو
- `GET /v1/credit` اعتبار
- `GET /v1/line` خط‌ها

وضعیت تحویل: `1` رسیده، `2` نرسیده به گوشی، `3` رسیده به مخابرات، `4` نرسیده به مخابرات، `5` رسیده به اپراتور، `6` ناموفق، `7` لیست سیاه، `8` نامشخص.

## کدهایی که در ارسال به آن‌ها برمی‌خوریم

| کد | معنی |
|---|---|
| 10–14 | کلید یا حساب نامعتبر، غیرفعال، محدود به IP، یا معلق |
| 102 | اعتبار کافی نیست |
| 104 | شماره نادرست |
| 105 | بیش از ۱۰۰ شماره |
| 113 | قالب پیدا نشد |
| 114 | مقدار پارامتر بیش از ۲۵ کاراکتر |
| 115 | شماره در لیست سیاه سامانه |
| 116 | نام یک پارامتر مقدار ندارد |
| 119 | پلن اجازهٔ قالب شخصی نمی‌دهد |
| 122 | قالبِ در حال بررسی قابل ویرایش نیست |
| 124 | پلن فعلاً فقط قالب OTP را می‌پذیرد |
| 125 | متن قالب متغیر `#PARAMETER#` ندارد |

## Sandbox

کلید Sandbox جدا از کلید عملیاتی ساخته می‌شود. همان URLها را می‌زند، پیام واقعی نمی‌فرستد، اعتبار کم نمی‌کند و قالب واقعی را عوض نمی‌کند.
قالب آزمایشی Verify شناسهٔ `123456` و متن `کد تایید شما: #CODE#` است.

## جای این قرارداد در CRM

| تنظیم | محل |
|---|---|
| کلید | `SMS_API_KEY` در env |
| خط متن آزاد | `sms.config.lineNumber`، وگرنه `SMS_SENDER_LINE` |
| قالب Verify | `sms_templates.provider_template_id` با `provider_status = 2` |
| ارسال | `shared/sms.ts` → `smsirVerify` و `smsirBulk` |
| خواندن گزارش | `smsirRead`؛ Copilot بین هر GET دو ثانیه فاصله می‌گذارد |

جزئیات استقرار در `docs/sms.md` است. دو کپی `shared/sms.ts` (داخل CRM و `/project/kermanshahcart/shared/sms.ts` روی سرور) باید هم‌هش بمانند.
