# Front-end diagnostic report

> Generation time: 2026-10-20 18:00 UTC
> Question type: build / runtime / ui
> Scope of influence: Carla CRM copilot bar and tab, local Vite

## Problem description

- The new assistant had to be checked before it limped: layout, shared thread, send failure, and the existing Vite build break.
- Local branch `main`, uncommitted `src/App.tsx` and `src/components/CopilotWidget.tsx`.

## Reproduction path

1. `npx vite build`, then `npx vite --host 127.0.0.1 --port 5173` with the API on `PORT=5000`.
2. Open the supervisor dashboard, expand the bar, send «مانده امروز؟», open «ادامه در تب», return to the dashboard.
3. Desired: one thread, one error line, no console exception, build succeeds.
4. Actual before the fix: cashier landing tab was the assistant; a failed send repeated the error in the open bar; Vite could not resolve Vazirmatn.

## Evidence collected

- `npm run` build previously failed because `node_modules/@fontsource/vazirmatn` was missing. Lockfile already pins `5.3.0`. After install, `vite build` wrote the four woff2 files into `dist/assets`.
- Live page at `http://127.0.0.1:5173/`: bar sits above the dashboard cards. Expand shows the input. «ادامه در تب» keeps the same user message.
- `POST /api/copilot/chat` returned 503. Body text: سرویس هوش مصنوعی پیکربندی نشده است (`COPILOT_API_URL`).
- Browser `errors` stayed empty.
- Sidebar order after the fix: داشبورد، کارآموزان، دوره‌ها، ثبت‌نام، حسابداری، دستیار مالی.

## Hypothesis and Verification

| Hypothesis | Verification Method | Results |
| --- | --- | --- |
| Copilot placed before students makes the cashier's first visible tab the assistant | Read `visibleNav[0]` fallback in `App.tsx`, then confirm sidebar order in the browser | Confirmed, then fixed |

## Root cause

- Nav order, not a router bug: the default tab falls through to the first visible item.
- The collapsed-bar error preview stayed visible after expand, so the same string rendered twice.
- The font package was declared and locked, but absent from `node_modules`.

## Fix content

- Moved the «دستیار مالی» item to after حسابداری.
- Error text is shown in the collapsed bar only. The open bar and the full tab keep a single error line.
- Installed the already-locked font package. `package.json` and `package-lock.json` were not edited.

## Verification results

- `npx vite build` completed and emitted `dist/index.html` plus the Vazirmatn woff2 assets.
- Browser: dashboard bar, expand, 503 error, tab with the same message, back to the dashboard with the error once. No page errors.
- Not verified: a successful model reply, because this API process had no `COPILOT_API_URL`. Cashier login was not clicked; the first-tab fix is from the nav order check.

## Residual risk

- Chat still cannot answer until `COPILOT_API_URL` and `COPILOT_API_KEY` are set on the API that Vite proxies to (`localhost:5000` in `vite.config.ts`; the server default port is 3000).
- GitHub Pages does not include this UI until a commit and publish.
